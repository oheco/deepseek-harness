# Native launcher reference

English | [中文](README.zh.md)

This local-only library exposes `import launcher from 'libdsh_launcher.so'` with the required `start(config): void`, `snapshot(): LaunchSnapshot`, and `stop(): void` methods, plus `probe(config): void` and `probeSnapshot(): ProbeSnapshot`. [The declarations](types/libdsh_launcher/index.d.ts) own the complete field list. The application entry package must depend on `file:./src/main/cpp/types/libdsh_launcher` and point its external native build to this directory's [CMakeLists.txt](CMakeLists.txt).

The sources are split into `launcher_util.*` (descriptor ownership, config field bounds, the fork-child failure record, inherited-descriptor closure), `launcher_config.h` (`LaunchConfig`), `supervisor.*`, `probe.*`, and `napi_bridge.cpp`. The static `dsh_supervisor` target carries the supervisor and the probe, links `dsh_launcher_core`, and `dsh_launcher.so` links that target plus `libace_napi.z.so`; no third-party dependency is added.

## Inputs and environment

Every path must be absolute, nonempty, shorter than `PATH_MAX`, and contain neither NUL nor line breaks. `nodePath` and `homeDir` cannot contain the `PATH` separator `:`. Node must already be a regular executable signed for the device; the launcher never downloads, signs, or modifies it. `dshEntry` is an existing readable built DSH entry. `homeDir` and `workDir` must already exist and are never created or chmodded. Port is an integer from 0 through 65535, and startup timeout is an explicit integer from 1 through 86400000 milliseconds.

File preflight uses the operations the launcher itself performs, because OHOS `access()` is unreliable in both directions: `access(R_OK)` reports success for a mode 0000 file, and `access(X_OK)` reports success for a directory with no search permission, while the real `open` or `chdir` fails with `EACCES`. `dshEntry` must `stat` as a regular file and survive `open(O_RDONLY | O_CLOEXEC)`, which is closed immediately. `nodePath` must `stat` as a regular file, carry at least one execute mode bit (`st_mode & 0111`), and survive the same real open. A missing execute bit is reported as `execute bit [path]: errno=13 (Permission denied)`; a real open denial is reported as `open file [path]: errno=N (strerror)`. Nothing is chmodded, and no permission is granted. The execute mode bit is a mode-bit check only: it does not establish that SELinux permits the exec, and the child's `execve` error channel owns that verdict, reported as `execve signed Node [path]: errno=N (strerror)`.

HOME/work preflight checks that each path resolves to a directory, without requesting directory-listing permission: Linux/OHOS uses `O_PATH | O_DIRECTORY`, and other platforms use `stat`. Final directory symlinks are followed, unlike private storage paths; the configured strings are not canonicalized or rewritten in `HOME`, `PATH`, or the child `chdir` argument. The final HOME directory need not be searchable merely to supply environment values. The child's actual `chdir(workDir)` checks cwd search permission, and failures retain the `chdir` stage, configured path, errno, and reaped exit status. Missing paths, non-directories, symlink loops, and inaccessible ancestors remain errors; the launcher grants no permissions and does not fall back to another cwd.

Pass `context.filesDir + '/dsh-launcher'`, `context.cacheDir + '/dsh-launcher'`, and `context.tempDir + '/dsh-launcher'`, not their system-created 0770 roots. The worker walks each private path with `openat(O_NOFOLLOW)`, creates missing components with mode 0700, and verifies the final directory's owner and exact 0700 mode. It applies the same rule to `filesDir + '/dsh'`. Existing insecure directories and symlinks are rejected rather than chmodded or replaced. It never changes shared `~/.dsh` links. The trusted application-private ancestors must not be concurrently renamed by another actor with the same UID.

The child receives exactly six environment entries, with no inherited terminal variables, API credentials, `NODE_OPTIONS`, proxy settings, or library search overrides:

| Variable | Value |
| --- | --- |
| `HOME` | `homeDir` |
| `DSH_HOME` | `filesDir + '/dsh'` |
| `XDG_CONFIG_HOME` | `filesDir` |
| `XDG_CACHE_HOME` | `cacheDir` |
| `TMPDIR` | `tempDir` |
| `PATH` | Node directory + `:` + `homeDir + '/.oheco/bin:/usr/bin:/system/bin'` |

The executable arguments are exactly `nodePath, '--expose-internals', dshEntry, 'web', '--host', '127.0.0.1', '--port', String(port), '--no-open'`; no shell performs splitting. Cwd is `workDir`, stdin is `/dev/null`, and stdout/stderr use independent pipes. Inherited non-stdio descriptors are closed. OHOS uses a precomputed descriptor limit and individual async-signal-safe `close` calls: its application syscall policy can raise SIGSYS for `close_range` despite the SDK declaring it. Private-directory traversal uses `O_PATH` on Linux/OHOS so searchable 0711 ancestors do not require directory-listing access. Environment isolation does not prevent DSH itself from reading a `.env` or credentials explicitly present in its working directory or configured storage; use an empty isolated cwd for credential-free validation.

## Lifecycle and readiness

A persistent native worker owns all filesystem calls, fork, pipe polling, timeout handling, and reaping. `start` validates bounded fields and queues work; a second start throws until the previous run finishes, including while stopping. `snapshot` copies a mutex-protected in-memory record and at most 16 KiB of logs; no worker I/O holds that mutex. `stop` immediately publishes `stopping`, clears the URL, and requests termination without joining. Calling stop when idle or terminal immediately settles to stopped without discarding the last diagnostic; this also supports the UI's stop-before-retry flow.

Only a newline-terminated stdout line matching the entire `dsh web: http://127.0.0.1:<port>/?token=<base64url>` announcement can make the run ready. The port must be 1..65535 with canonical decimal notation, exactly equal to a nonzero requested port. An optional exact ` (LAN: http://<IPv4>:<same-port>/?token=<same-token>)` suffix is validated but never used as the WebView URL. ANSI CSI/OSC escapes may span chunks and are removed before parsing; invalid controls, oversized lines, incomplete escapes, stderr announcements, and EOF without newline never signal readiness. Line buffering is independently capped at 8 KiB per stream.

The authenticated URL is retained only in memory and cleared on stop, timeout, or observed exit. Do not persist or log snapshots wholesale: their `url` is a credential. Logs deliberately withhold all arbitrary child text, including apparently harmless fragments, because an unknown token can appear before readiness or across streams/lines. They retain fixed stdout/stderr classifications, discarded-line reasons, readiness summaries, and supervisor-generated stage/path/errno, timeout, and exit diagnostics. This fail-closed choice prevents loader stack traces from being shown verbatim; keywords alone cannot establish that a line contains no credential.

Each child has its own process group. Stop or timeout sends TERM; after 750 ms the worker sends KILL to that owned group and reaps its leader. `waitid(WNOWAIT)` holds the leader PID until the final group signal, preventing PID recycling into an unrelated group. Unexpected exit, including exit code 0 after readiness, is an error; a user-requested stop is stopped. `exitCode` is -1 until reap, an ordinary exit status on normal exit, or 128 plus the terminating signal. `pid` becomes zero after reap. The worker never attaches to an existing service or signals a port owner.

On Linux/OHOS, a direct `prctl(PR_SET_PDEATHSIG, SIGKILL)` syscall plus the parent-PID race check provides best-effort parent-death cleanup for the direct Node child. It is not inherited by grandchildren, and descendants that deliberately leave the process group cannot be guaranteed cleanup after abrupt application death. No app-wide signal disposition or subreaper setting is changed. Other code must not reap this library's children or set `SIGCHLD=SIG_IGN`/`SA_NOCLDWAIT`.

TERM/KILL issuance is bounded, but a kernel-uninterruptible process cannot be promised a bounded reap. If still unreapable two seconds after KILL, the record remains stopping with an explicit diagnostic and restart disabled; it does not lie about completion or abandon ownership. Async NAPI environment cleanup keeps the module alive until the worker joins. A thread-creation failure in that cleanup falls back to a synchronous join rather than unloading live native code.

## Capability probe

`probe(config)` starts read-only device checks on a separate persistent worker and returns at once; `probeSnapshot()` copies `{ running, report }` under the probe's mutex, so polling never waits for a check. `start(config)` supplies its own probe for the same paths, and a rejected start creates none. A probe is never reused: a new call replaces the instance after the previous report was published, and a call while a probe is still running is a `logic_error` rather than a silent restart. The probe validates the same fields, creates a missing private directory component at 0700 for its own write and copy checks, and never chmods, replaces, or deletes an existing file or directory.

The report is at most 8 KiB of newline-terminated printable ASCII, each line starting with `OK `, `FAIL `, or `INFO `. Every `http(s)://` run up to the next whitespace becomes `[URL redacted]`, so a token-bearing URL cannot reach a caller even when a command prints one; command output contributes only its first line, cleaned and cut to 120 characters. Each check reports independently and one failure cannot hide the checks after it: identity (uid, euid, gid, supplementary groups), `stat` mode/uid/gid for `homeDir`, `workDir`, `nodePath`, and `dshEntry`, real opens of `dshEntry` and `nodePath`, a create-write-unlink in `filesDir`, `nodePath --version`, `/usr/bin/zsh -c "printf probe-ok"`, the system shell through `execve`, an app-private mode 0700 copy of `/system/bin/sh` executed with `-c "printf probe-ok"`, and a summary line. The private-copy check is the deciding fact for a self-contained bundle: it reports whether this device runs an app-private executable image, and an unsigned copy is expected to be refused by platform signing policy.

Each exec check forks one child with its own pipes and descriptor bound, uses `fork` + `execve` with no shell splitting, reports an exec failure through the same `ChildFailure`-style record (`stage`, `errno`, `path`) over a dedicated pipe, and caps the check at five seconds: TERM first, then KILL after 750 ms, always reaping its own child. The probe never touches the supervisor's child, process group, or descriptors, and never signals a process it did not fork.

## Verification limits

[Native fixture commands](../../../../tests/native/README.md) compile and sign standalone executables on HarmonyOS and link the bridge against the installed SDK without requiring a system permission API. They are not proof that an ordinary signed HAP can execute a separately installed Node binary, access shared storage paths, use the same process/signal operations, or keep its service alive under application suspension. HAP packaging/signing, ArkTS import and async cleanup behavior, WebView integration, SELinux execution policy, and ordinary-HAP lifecycle remain device-application checks. A probe run from the fixture recipe reports the terminal domain's own answers, so its identity, group list, and shared-path results are not an ordinary HAP's. No real DSH service is started by the fixture recipe.
