# 本地验证记录

本工程未发布、未推送、未接入正式软件索引，也没有替换正在使用的 dsh 安装。它是供用户构建签名并安装验证的源码工程，不是已完成普通 HAP 端到端验收的发行版。

## 真机能力边界（已确认）

普通调试签名（DevEco 自动签名）下，应用进程 `uid=20020187`、附加组 `1097,3099`，实测：

| 检测项 | 结果 |
| --- | --- |
| 写应用私有目录 | ✅ OK |
| 执行 `/system/bin/sh -c printf probe-ok` | ✅ exit code 0，输出正确 |
| `open` 共享目录中的 Node 与 DSH 入口 | ❌ `errno=1 EPERM` |
| 执行私有目录中的 ELF 副本（`/system/bin/sh` 拷贝 + 0700） | ❌ `errno=13` |
| `/usr/bin/zsh` | ❌ 应用沙箱内不存在（`errno=2`） |
| 系统 Node | ❌ `/system/bin/node`、`/system/nodejs`、`/usr/bin/node` 均不存在 |
| 共享文件权限 | `-rw-rw----`，属主 `20001006`、组 `1006`；应用不在该组 |

结论：应用内直接启动所需的**读取与执行两项权限都不具备**；系统没有可用的 Node，因此“把运行时装进 HAP 自己执行”的自包含方案同样不成立（私有目录不能执行 ELF）。工程据此改为两步模式：终端启动服务并写日志，应用读日志取地址并打开。

## 需要在实际 HAP 中验证

1. **两步模式连通**：在终端执行首页给出的命令后，应用应在一秒左右发现地址、确认可连接并打开页面。若等待区提示无法读取日志，点“选择日志文件”授权；若页面报 401，说明日志里是过期地址，重新执行命令即可。
2. **遗留日志**：先执行一次命令再停掉服务（`kill` 该进程），然后打开应用：应停留在等待界面而不是打开一个失效页面。
3. **全窗口 WebView**：打开后页面占满窗口，没有标题栏/返回/设置；系统返回键优先回退网页历史。
4. **真实对话与工具**：在 Web 界面完成一次真实对话，并让 DSH 在临时目录执行一个无害 zsh 命令。
5. **端口与并存**：多次执行命令（不同端口）应各自打开对应页面，且不影响你已在 9000 运行的服务。
6. **品牌**：确认 Web 界面显示的品牌与你安装的 `dsh` 构建一致（上游原版品牌需要重新构建并安装启用 `official` profile 的 `dsh`）。
